[Binance public historical-dataset terms](https://github.com/binance/binance-public-data/blob/master/TERMS_AND_CONDITIONS.md) explicitly require a separate enterprise license for commercial use. ## Proposed integration contract (approval required)

- Keep market data separate from account holdings and send no account/address data to a market vendor. Fetch only from approved hardcoded server endpoints after existing Access verification; no client-selected URLs. Reject cross-origin requests and bound request/response size, timeout and instrument count. Secrets remain in Pages bindings.
- Normalize exact decimal values with explicit units, instrument, venue list, source update time and response completion time. Funding requires actual settlement interval and fraction/percent convention; annualization is excluded. OI requires contract multiplier or base/quote units. Liquidations require window start/end, long/short convention and disclosed event gaps.
- Proposed bounded server cache: maximum 20 public instrument/metric keys, 60-second TTL, single flight per key, no background refresh. Clear source-update and cache-age labels. Explicit refresh only; obey vendor Retry-After. If quota or timeout occurs, show unavailable or explicitly stale cached observations, never zero or reconstructed estimates. No indefinite cache or request logs with credentials/payloads. Final TTL depends on vendor caching permission.
- No server fetching or cache is implemented while sources are unapproved. The typed server provider is an interface plus a disabled implementation; it is not evidence of successful integration. A live adapter needs runtime schema validation, unit conversion and window/coverage tests before use.
